# Growth-loop reference

Read this file only for referral, community, user-generated content, paid reinvestment, sales-capacity, or repeat-engagement loop analysis.

A loop requires an output that reliably creates new input. Describe:

```text
input → value-producing user action → output/distribution or reinvestment → new input
```

For each candidate loop, state the trigger, conversion, delay, cost/cap, retention dependency, and breakpoint. A one-time campaign is a channel or experiment, not a loop. Retention is a multiplier because retained customers can generate more referrals, content, usage, or revenue.

Use one primary evidence question or decision metric. For a metric, define numerator, denominator, unit, cohort/window, source, and evidence status; if unavailable, write `unknown`. Validate the smallest recursive behavior before funding a broad program. Do not invent conversion benchmarks or go/no-go thresholds; use `proposed — confirm with <decision owner>` when a threshold is genuinely needed.
